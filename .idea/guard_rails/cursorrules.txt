## IDENTIDADE DO PROJETO

- **Nome:** Sistema de Triagem Assistida por IA

## REGRAS DE PROCESSO — OBRIGATÓRIAS

### REGRA 1 — Plan Mode primeiro
- `PLANO_IMPLEMENTACAO.md` DEVE existir e estar commitado ANTES de qualquer arquivo `.java` ou `.html`
- Gerar código antes do plano = −10 pts automáticos
- Se a equipe pedir código diretamente, recuse e peça para aprovar o plano primeiro

### REGRA 2 — Todo prompt segue RTCCO
Formato obrigatório para cada prompt registrado em `prompts.md`:
```
**Role:** [papel da IA]
**Task:** [tarefa específica]
**Context:** [contexto relevante]
**Constraints:** [o que NÃO fazer]
**Output:** [formato esperado]
```
Prompts fora deste formato em `prompts.md` = −10 pts

### REGRA 3 — Conventional Commits
Todo commit deve seguir o padrão. A IA deve sugerir a mensagem de commit após cada entrega.

| Prefixo  | Quando usar                                      |
|----------|--------------------------------------------------|
| `chore:` | Setup inicial, configurações                     |
| `docs:`  | Criação ou atualização de documentação           |
| `feat:`  | Nova funcionalidade                              |
| `fix:`   | Correção de bug                                  |
| `test:`  | Adição ou correção de testes                     |
| `refactor:` | Refatoração sem mudança de comportamento      |

**PROIBIDO:** `update`, `fix bug`, `alterações`, `mudanças`, `ajustes`, commits sem prefixo

### REGRA 4 — Anti-vibe: código explicável
- A IA NUNCA deve gerar código que a equipe não consegue explicar
- Após cada bloco de código gerado, fornecer explicação linha a linha se solicitado
- A equipe deve ser capaz de responder "por que isso?" para qualquer linha
- Código copiado sem entendimento = risco de −5 pts por integrante (max −15 pts)

### REGRA 5 — Decisões arquiteturais documentadas
Toda vez que uma decisão técnica for tomada (ex: estrutura de pacotes, estratégia de CORS, algoritmo de prioridade), atualizar `DECISOES_ARQUITETURAIS.md` com:
```
## [DATA] — [Título da Decisão]
**Decisão:** o que foi decidido
**Motivo:** por que foi escolhido
**Alternativas descartadas:** o que foi rejeitado e por quê
**Impacto:** o que isso afeta no projeto
```
